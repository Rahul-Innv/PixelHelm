# pixelhelm-directions — honesty bindings + per-project registers

> Read this when the target surface renders claims about money/safety/facts, OR to load the active
> project's register before judging directions. Two parts: (1) honesty bindings — NON-negotiable
> trust duties that outrank looks; (2) registers — the per-project personality that must NEVER be
> homogenized. Sources: the owner's direction-mockup process notes (honesty bindings); the
> build-spec register mandate; `profiles/*.json`.

## Part 1 — Honesty bindings (data products)

When a surface renders claims about money, safety, or facts, the design carries trust duties that
**outrank looks**. These are NOT taste — never trade them for a cleaner mockup, and never let a
direction win that violates them.

- **Unverified never wears the positive verdict's clothes.** An unverified estimate never uses the
  positive verdict's color or fill; its hedge copy sits **adjacent to the number**, not in a
  footnote. "Unverified" must read hedged — never alarming, never positive.
- **"No data" is an honest empty state** — never a stale or seeded number styled as current. A
  blank-but-intentional state, clearly labeled, beats a confident-looking lie.
- **Every number's WHY is one click away** — source count, freshness, method must be at most one
  click/expand from the displayed value.
- **Never display an invented statistic.** A real review caught a hardcoded `Math.max(2, …)`
  "seller count" — fabricated confidence is a trust violation; delete it. Mockups render REAL data;
  synthetic rows added only for state coverage must be clearly marked as synthetic.

Carry these into EVERY direction. A direction's signature can be bold; its honesty cannot be
negotiable. (The active project's register tunes the *tone* of a hedge — see below — but never
removes the hedge.)

## Part 2 — Per-project registers (DO NOT homogenize)

The per-project REGISTER is a first-class owner input. The same craft canon
applies to all projects; the **register differs**. Judge each direction AGAINST the active
project's register — `pixelhelm-judge`'s "creative distinction" lens scores against that register,
not a global ideal. Load the machine profile from `${CLAUDE_PLUGIN_ROOT}/profiles/<project>.json`
(token module, banned color clusters, allowed-raw-color files) and the human register below.

### A regulated trust portal — fintech-grade serious-trust
Calm, restrained, never playful or cartoonish (Mercury / Vanta / Stripe). Single locked teal
palette; the operator app uses a disciplined operator register, the end-user portal
stays CALM; the override role is NEUTRAL (never amber). The profile's banned
clusters include the generative-AI cyan fingerprint and the default purple->pink gradient. A
direction here earns trust through discipline, not delight.

### A warm consumer app — playful-premium-fun-but-calm
Characterful and warm, but calm — the personality of Things 3 / Gentler Streak executed with
Linear-grade discipline. Rounded, motion-delight, encouraging tone; this is the CORRECT register
for a personal daily-wellness app. Color is information: terracotta = the hero-metric accent, sage =
primary/success, amber/red reserved for over-cap/urgent only. One rationed accent, a 4-step
surface ladder, 2 locked weights, one metric as the unmistakable hero. The full register, locked
constraints, and steal-set for this example lived in the project's brief (Oura / MacroFactor /
Linear / Things 3 / Gentler Streak). Encouraging numbers; reframe negatives ("room for ~40 g
more"), never failure-red.

### An analyst data product — credible analyst-terminal
Dense, sourced, no-red (Bloomberg x Wikipedia: Koyfin / Perplexity / Raycast). Information density
is a feature; red is reserved for errors only (a momentum gauge, not alarm coloring). Trust comes
from sourcing and credibility, not warmth.

### The rule
A direction that reads warm-premium-fun is a SUCCESS for the warm consumer register and a FAILURE for the trust register — same
craft, opposite register. Never carry one project's personality onto another. When the active
project is unknown, ask the router/owner which project (and surface) before distilling directions —
do not default to a generic look.
