# C8 — Persona Bench (think-aloud consumer read) · *T2 W3 A1*

**Trigger:** a consumer-facing surface where a NON-EXPERT end user reads or enters
consequential data — money, health, deals, legal acknowledgments, forms. (An
analyst-terminal surface for trained operators does not seat this bench.)

**Why a formal seat:** verified twice-over (KB **L-017**, status VERIFIED): on both Lentova
(recipe editor) and a candidate-portal disclosures surface, persona reads independently
surfaced HIGH-severity comprehension bugs that a 5-lens discipline council AND a craft pass
had both structurally missed (a protective cooling-off period read as a signing DEADLINE; an
acknowledgment read as SIGNING the deal; a whole-recipe total misread as one serving). Expert
lenses grade quality; they do not simulate a first encounter.

## Staffing (2 diverse personas minimum — diversity is the mechanism)

1. **The careful, anxious first-timer** — e.g. a 72-year-old non-technical reader, or an
   anxious first-time buyer. Reads everything, trusts nothing, fears making a mistake.
2. **The time-pressed skimmer** — scans for the number/verdict/button, acts in seconds.

Each persona is an independent subagent given: the rendered PNG(s) (personas read pixels,
same as every juror), one line of product context, and the surface's core tension. Each
THINKS ALOUD through the exact screen: *what is this? what would I do? what would I get
wrong? what would I not notice?* — and returns ranked confusions/misreads/wrong-data risks,
each with the smallest fix.

## The convergence rule (what elevates a finding)

- BOTH personas independently flag the same confusion → **HIGH** finding (constraint-grade).
  Convergence across diverse personas is the strong signal (the L-017 empirical core).
- One persona flags it → advisory; the chair weighs it like any single-lens note.

## Verdict class + aggregation

C8 findings are **CONSTRAINTS** — excluded from the winner-ranking mean, register-subordinate
like every composite (the aggregation contract in `deep-pass-composites.md` governs). C8
never out-ranks the register gate and never substitutes for Norman: it catches what expert
simulation of a novice cannot.

## When it also runs pre-build

`design-direction` may seat the same bench on direction MOCKUPS (a confusion fixed pre-code
is the cheapest fix of all — the Lentova pattern: persona-audit the mockup, fix, re-render,
then build). The council seat re-runs on the BUILT surface; a mockup pass does not exempt it.

## Honest bounds

- A persona subagent is a simulation, not a user test — it finds comprehension hazards, it
  does not measure task success. Treat its output as a review lens, never as user research.
- Personas read the RENDERED state they are given: keep the render self-consistent (KB L-022)
  or the bench chases artifacts.
