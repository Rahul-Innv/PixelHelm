# Security policy

## Supported candidate

Only the current private `2.0.x` candidate is under active qualification. Earlier
`design-*` identities are compatibility metadata and are not independently supported
canonical capabilities.

## Report a vulnerability privately

Do not include a vulnerability, credential, private path, or exploit detail in a
public issue. Use the repository host's private vulnerability-reporting channel after
the owner enables and verifies it. Until that channel exists, use an already-established
private channel with the project owner. If neither is available, retain the report
locally and wait for a private contact path rather than publishing it.

Include the affected version or commit, the smallest safe reproduction, impact, and
whether a secret may have been exposed. Never paste a live secret; rotate it first.

## Response boundary

No response-time promise is made while the project remains private and inactive.
Provider contact, credential rotation, history rewrite, publication, and host changes
require separate owner authorization.
